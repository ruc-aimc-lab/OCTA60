# OCTA60

OCTA60 is a benchmark for cross-modal fundus image registration between optical coherence tomography angiography (OCTA) and wide-field color fundus photography (wfCFP) under large field-of-view (FoV) disparity. See our [MMM 2026 paper](https://arxiv.org/abs/2512.12657) for details.

# Highlights

- **60 OCTA–wfCFP image pairs at 1000 × 1000 pixels**.
- **653 manually annotated point correspondences**, with 10–16 per image pair.
- **Large FoV disparity** between OCTA (FoV ~ 40°) and wfCFP (FoV ~ 90°) images.

Image IDs range from `001` to `060`. For each image pair, the OCTA image, wfCFP image, annotation file, OCTA vessel map, and wfCFP vessel map all use the same ID as their filenames.

- `Annotations/`: manually annotated point correspondences. The `mmm26/` subfolder contains annotations used in our MMM 2026 paper, with one `{ID}.txt` file per image pair.
- `ImageSets/`: `OCTA60.txt` lists the 60 image IDs, one per line, from `001` to `060`, in evaluation order.
- `ImageData/`: fundus images, stored as `{ID}.png` in the `OCTA/` and `wfCFP/` subfolders.
- `VesselData/`: Vessel maps generated by [UNet_DCP](https://ieeexplore.ieee.org/abstract/document/10888001), stored as `{ID}.png` in the `OCTA/` and `wfCFP/` subfolders.
- `WrappedSourcePoints/`: transformed source annotation points in the target wfCFP coordinate system for evaluation, stored in a JSON file. `CARe.json` contains the CARe predictions.
- `scripts/`: evaluation and prediction format checking code.
- `Cross-modal Fundus Image Registration under Large FoV Disparity.pdf`: our MMM 2026 paper introducing CARe and OCTA60.

# Annotation Format

Each `OCTA60/Annotations/mmm26/{ID}.txt` file has a pair of correspondence points per row, stored as four space-separated normalized coordinates with six decimal places:

```text
x_OCTA  y_OCTA  x_wfCFP  y_wfCFP
```

An example of an annotation file:

```text
0.283715 0.196842 0.402638 0.368917
0.617493 0.428156 0.541872 0.472305
0.394268 0.753921 0.448516 0.609734
...
```

# Prediction format

The evaluation code takes a **UTF-8 JSON file** as input, such as `WrappedSourcePoints/CARe.json`. This file stores the normalized coordinates obtained by transforming the annotated OCTA points into the wfCFP coordinate system using the registration result. The file must contain one JSON object with the following structure:

- **Key:** include every image ID listed in `OCTA60/ImageSets/OCTA60.txt`.
- **Value:** an array of annotated OCTA points transformed into the wfCFP coordinate system according to the registration result, written as `[[x1, y1], [x2, y2], ...]`.
- **Missing points:** use `[]` to preserve the position of each point for which no correspondence is successfully established after transformation.
- **Failed registration:** use an empty array `[]` to indicate failed registration for the entire image pair. The corresponding image ID must still be present.
- **Point correspondence:** for each non-empty predicted point array, the number of entries must exactly match the number of rows in `OCTA60/Annotations/mmm26/{ID}.txt`. The first predicted point corresponds to the first annotation row, the second to the second row, and so on.

The following excerpt shows the transformed points for image ID `001` and marks image ID `002` as failed. A complete submission must also include every remaining required ID; see `WrappedSourcePoints/CARe.json` for a complete file:

```json
{
  "001": [
    [0.347883, 0.394041],
    [0.428049, 0.350214],
    [0.62342, 0.627309],
    [0.516026, 0.417407],
    [0.455447, 0.596122],
    [0.666075, 0.350182],
    [0.338318, 0.67197],
    [0.531706, 0.562973],
    [0.307842, 0.644995],
    [0.321568, 0.338461]
  ],
  "002": [],
  ...
}
```

Run the checker before evaluation:

```bash
python scripts/pred_format_check.py WrappedSourcePoints/CARe.json
```

If the format is valid, you can see:

```text
PASS: WrappedSourcePoints/CARe.json | Prediction File format is valid.
```

If the format is invalid, you can see, for example:

```text
FAIL: 1 error(s) found.
1. '001'[0] (row 1): Point Cord Format Error
  Fix: Provide exactly two coordinates in x, y order, or use [] for a missing point.
```

# Run Evaluator

Run the following command to evaluate the prediction file:

```bash
python scripts/evaluate.py WrappedSourcePoints/CARe.json
```

The metrics follow the [MMM 2026 paper](https://arxiv.org/html/2512.12657v1):

- **MEE:** median Euclidean error.
- **MAE:** maximum Euclidean error.
- **Failed / inaccurate / acceptable rates:** registration fails if transformed annotated source points cannot be obtained. Otherwise, it is acceptable when MEE < 20 pixels and MAE < 50 pixels, and inaccurate if either condition is not met.
- **AUC@25:** the average fraction of pairs whose MEE is below each integer threshold 1, 2, …, 25 pixels. Failed pairs remain in the denominator.

If everything is correct, for the provided `WrappedSourcePoints/CARe.json`, you should see:

```text
Failed: 0 (0.00%)
Inaccurate: 0 (0.00%)
Acceptable: 60 (100.00%)
AUC@25: 0.928000
```
